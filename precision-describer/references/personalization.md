# Personalization

Use this reference when the user wants descriptions adapted to personal taste or when enough examples exist to infer preferences.

## Preference signals

Look for:
- repeated vocabulary choices
- sentence length and density
- tolerance for abstraction
- preferred emotional temperature
- explicit requests like "more restrained" or "less corporate"

## Comparative preference workflow

If the user asks for options or reacts to alternatives:
1. generate 2-5 distinct variants
2. make the differences legible
3. infer preference from the user's selection or rejection
4. carry that preference into the next pass

Useful contrast axes:
- restrained vs vivid
- technical vs everyday
- elegant vs blunt
- concise vs layered
- insider vs general-audience

## Using the user's own writing

When the user provides writing samples:
- copy structural tendencies, not exact phrasing
- preserve any recurring terms they seem attached to
- avoid overfitting to accidental quirks or weak sentences

## Constraint handling

If the user wants specific words, references, or stylistic markers included:
- treat them as hard constraints unless they directly conflict with clarity
- if a requested term weakens precision, say so and offer a nearby alternative
