# Evaluation

Use this reference only when the user wants to test, compare, or improve the skill itself.

## Evaluation targets

Check whether outputs are improving along these axes:
- ambiguity reduction
- audience fit
- domain fit
- tonal fit
- user preference fit
- explanation quality when teaching mode is used

## Lightweight evaluation loop

1. collect a small set of source descriptions
2. generate variants with a clear difference in strategy
3. compare outputs with a stated criterion
4. inspect which changes users prefer and why
5. edit the skill only when the failure pattern repeats

## Failure patterns to watch

- more specific but less accurate
- more technical but less useful
- more vivid but tonally off
- more personalized but too imitative
- too many alternatives without a clear recommendation

## Editing rule

When proposing a change to the skill:
- name the failure mode
- name the instruction that should change
- make the smallest viable edit
- rerun the same examples if possible
