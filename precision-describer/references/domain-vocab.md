# Domain vocabulary

Use this reference when the user wants domain-specific precision rather than generic sharpness.

## Selection rule

Choose vocabulary that increases clarity for the target audience. Avoid terms that are narrower but less legible to the reader.

## Domain patterns

### Technical

Prefer:
- mechanism over impression
- specific constraints over broad capability claims
- measurable behavior over vague evaluation

Examples:
- "fast" -> "low-latency" or "completes in under 200 ms"
- "reliable" -> "idempotent under retry" or "maintains 99.9% success rate"

### Mathematical

Prefer:
- named structures
- explicit relationships
- defined properties

Examples:
- "goes up quickly" -> "grows exponentially"
- "roughly even" -> "uniformly distributed" when that is actually true

### Literary

Prefer:
- image-bearing words
- tonal precision
- connotative accuracy

Examples:
- "sad" -> "mournful", "desolate", or "wistful" depending on texture
- "strange" -> "uncanny", "surreal", or "disorienting"

### Commercial

Prefer:
- audience-relevant value
- differentiation
- concrete outcomes

Examples:
- "good for teams" -> "reduces handoff friction across product, design, and engineering"
- "easy to use" -> "usable with minimal onboarding"

### Colloquial

Prefer:
- natural phrasing
- socially legible wording
- concise idiom when it improves fit

Examples:
- "very precise" -> "dialed in"
- "awkwardly formal" -> "stiff"

## Cross-language note

If another language or idiom expresses the concept more precisely, use it only if:
- the user is likely to understand it
- the phrase carries meaning that is hard to preserve in translation
- you explain the nuance briefly when needed
